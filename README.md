# راستا — مدیریت ساده پروژه و تسک

برنامه فارسی و راست‌به‌چپ با Laravel 12، MySQL 8.4، Blade، Alpine.js و Tailwind CSS 4. مسیر اصلی: پروژه ← یک هدف اصلی ← مراحل ← تسک‌ها ← زیرتسک‌ها. مسیر اعضای تیم مستقل از مراحل محصول است.

## اجرا در سیستم توسعه

نیازمندی‌ها: PHP **8.4** با `ctype`, `curl`, `dom`, `fileinfo`, `intl`, `mbstring`, `pdo_mysql`, `tokenizer`, `xml`, `xmlwriter`؛ Composer 2؛ Node.js 22 یا جدیدتر؛ MySQL 8.4. برای تست‌های پیش‌فرض `pdo_sqlite` هم لازم است. فایل قفل فعلی با PHP 8.4 حل شده است.

```bash
composer install
cp .env.example .env
php artisan key:generate
```

در `.env` مقادیر `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` را برای دیتابیس خودتان تنظیم کنید. برای داده نمایشی، `APP_ENV=local` و `DEMO_PASSWORD` را به یک گذرواژه انتخابی خودتان تنظیم کنید. سپس:

```bash
php artisan migrate --seed
npm ci
npm run build
php artisan serve
```

ورود داده نمایشی: `sara@example.test` با گذرواژه‌ای که در `DEMO_PASSWORD` قرار داده‌اید. کاربران نمونه دیگر: `ali@example.test`، `niloufar@example.test` و `amir@example.test`. Seed فقط در محیط local/testing فعال است و اجرای مجدد آن داده‌های کاربر موجود را بازنویسی نمی‌کند. برای شروع بدون داده نمونه، تنها `php artisan migrate` را اجرا کنید و از صفحه ثبت‌نام حساب بسازید.

در توسعه رابط می‌توانید `npm run dev` را هم اجرا کنید. پس از تغییر Blade و در صورت فعال بودن کش، `php artisan view:clear` را اجرا کنید.

## محیط ابری فعلی

این محیط از PHP نصب‌شده بدون دسترسی ریشه در `/workspace/.runtime` و MySQL داخل Docker استفاده می‌کند. نصب و تازه‌سازی قابل تکرار:

```bash
bash scripts/setup-cloud.sh
```

راه‌اندازی سرویس‌ها:

```bash
bash scripts/start-cloud.sh
```

این اسکریپت MySQL را راه‌اندازی می‌کند، آماده بودن آن را با یک پرس‌وجوی واقعی می‌سنجد و سرور PHP را از پوشه `public` اجرا می‌کند. این روش به‌دلیل محل اختصاصی کتابخانه‌های PHP در محیط ابری جایگزین `artisan serve` شده است. برای دسترسی به CLI:

```bash
export PATH=/workspace/.runtime/bin:$PATH
```

پیش از تهیه snapshot از محیط، از دیتابیس خروجی بگیرید:

```bash
bash scripts/backup-cloud.sh
```

خروجی خصوصی در `/workspace/.runtime/rasta.sql` است و در Git قرار نمی‌گیرد. اسکریپت شروع فقط در صورت خالی بودن دیتابیس، این خروجی را بازیابی می‌کند؛ داده موجود را بازنویسی نمی‌کند. ماندگاری Docker volume در یک ماشین جدید تضمین نشده است؛ بازیابی در یک task جدید هنوز مستقلاً آزمایش نشده است. از checkout فعلی استفاده کنید؛ هر task ابری ایزوله است و نیازی به Git worktree نیست.

دانلودهای Composer در `composer.lock` به آرشیو HTTPS رسمی `codeload.github.com` اشاره می‌کنند، چون `api.github.com` در شبکه این محیط مسدود است. اعتبارسنجی TLS و امضای بسته‌های Debian غیرفعال نشده‌اند.

## آزمون‌ها

```bash
php artisan test
npm run build
npx playwright test
```

۲۵ آزمون PHP شامل ورود و ثبت‌نام، محدودسازی ورود، پروژه و هدف، دو نوع مرحله و ترتیب، تسک و زیرتسک، برچسب، نظر، فایل خصوصی، نقش‌ها، جلوگیری از دسترسی بین پروژه‌ها و اعتبارسنجی فارسی است. آزمون‌های پیش‌فرض از SQLite حافظه‌ای استفاده می‌کنند. همان مجموعه در محیط حاضر روی **دیتابیس جداگانه MySQL** نیز اجرا شده است. برای اجرای مجدد روی MySQL، دیتابیس آزمون جداگانه بسازید و هرگز دیتابیس برنامه را به تست ندهید:

```bash
DB_CONNECTION=mysql DB_DATABASE=rasta_test php artisan test
```

دو آزمون Playwright شامل جریان واقعی ساخت و ویرایش، مرحله داخل مودال، مرتب‌سازی، تاریخ شمسی، پیوست، نظر، تأیید تغییرات ذخیره‌نشده، و نمایش دسکتاپ/موبایل‌اند. سرور باید در حال اجرا باشد. مرورگر پیش‌فرض `/usr/bin/chromium` است؛ مسیر دیگر را با `CHROMIUM_PATH` تنظیم کنید. آزمون بصری داده نمونه و `DEMO_PASSWORD` در `.env` را می‌خواند و مقادیر آن را چاپ نمی‌کند. حساب‌های موقت آزمون دامنه `@browser.test` دارند.

## فایل‌ها و امنیت

- فایل‌ها در `storage/app/private/attachments` با نام تصادفی ذخیره می‌شوند. نیازی به `storage:link` نیست و این پوشه نباید عمومی شود.
- دانلود از `/attachments/{id}` فقط بعد از احراز هویت و کنترل عضویت پروژه انجام می‌شود.
- فرمت‌های مجاز: PDF، PNG، JPEG، WebP و TXT؛ سقف هر فایل ۵ مگابایت. نوع محتوایی و پسوند هر دو بررسی می‌شوند.
- نویسنده می‌تواند نظر خودش را ویرایش یا حذف کند. بیننده فقط دسترسی خواندن دارد. مالک اعضا و هدف را مدیریت می‌کند؛ اعضا روی مراحل و تسک‌ها کار می‌کنند.
- CSRF، نشست Laravel، هش گذرواژه، محدودسازی درخواست‌ها و خروجی متن امن در Blade/Alpine فعال‌اند. تاریخ در دیتابیس استاندارد و در رابط شمسی است.
- برای انتشار عمومی: HTTPS، `APP_DEBUG=false`، `APP_ENV=production`، `SESSION_SECURE_COOKIE=true` و تنظیم `APP_URL` لازم است. در آن محیط داده نمایشی نسازید. انتشار عمومی انجام نشده است.

## طراحی و پیش‌نمایش

فونت وزیرمتن محلی بسته‌بندی شده؛ نیازی به سرویس فونت خارجی نیست. توکن‌های رنگ، فاصله و شعاع در `resources/css/app.css` و اجزای مشترک در `resources/views/components` و `partials` هستند.

لینک مرجع `https://uja.seeddesignsystem.workers.dev/en/foundations` در شبکه این محیط با خطای CONNECT 403 مسدود بوده است. به همین دلیل **تطبیق دقیق با توکن‌های آن تأیید نشده** و پالت فعلی مستقل و قابل تغییر است. دامنه در پیش‌نویس شبکه اضافه شده؛ پس از اعمال دسترسی می‌توان توکن‌های واقعی را بررسی و جایگزین کرد.

پیش‌نمایش‌های تصویری در `/workspace/artifacts` تولید می‌شوند. فایل `rasta-preview.html` گالری مستقل و آفلاین این تصاویر است؛ برای مشاهده بدون اجرای Laravel مناسب است و عملیات ذخیره‌سازی برنامه را اجرا نمی‌کند. این محیط لینک عمومی قابل دسترسی برای وب‌سایت ارائه نمی‌کند.
